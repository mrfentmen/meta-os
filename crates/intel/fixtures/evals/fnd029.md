# FND-029: watchdog state keys + alert dedupe key shapes (Milo)

## What was already true before this run

Pax's Day 1 foundation commit (f5fbb3d, FND-004) defined the
layout in intel/store.py, including the `muse-bus:intel:wd:<nick>`
hash with fields last_seen / last_progress (unix seconds) /
claimed_jobs (comma-separated job ids). That definition was
never closed as FND-029, and intel/README.md still said the
task was "owed by Pax". No separate Pax sign-off message
exists in the repo; the definition lives in shared code.

## What this run added

- intel/store.py docstring: the second half of FND-029, the
  alert dedupe key shapes, written next to the wd hash entry:
  presence-stall / progress-stall / lease-risk as
  `<kind>:<nick>:<job>`; dead-dep / missing-dep as
  `<kind>:<job>:<dep>`; file-collision as
  `<kind>:<job>:<job>:<path>`; attempt-warning / attempt-exhaustion
  as `<kind>:<job>`; silent-room[:<room>]; budget-warning:<lane>;
  system-failure:<unit>; worker-restart:<nick>:<job>. Journal
  dedupe keys (ladder:<job>:<rung>, baton:<job>, park:<job>)
  are noted as living in their own modules.
- tests/test_intel_fnd029.py: 13 pinning tests. wd_key shape
  matches Pax's FND-004 layout; the docstring names the wd
  hash fields and every detector dedupe shape; one tick per
  detector family yields exactly the documented key (fixtures
  mirror tests/test_intel_watchdog.py's own shapes).
- intel/README.md: the stale "still owed by Pax" paragraph
  replaced with the shared-code status above.

## Verification

- New tests: 13/13 PASS (python3 -m unittest
  tests.test_intel_fnd029).
- Full suite by discover: 1686 tests = 1673 clean-tree
  baseline + 13 new, only the 2 known pre-existing
  environmental failures (bustools parity, live skill script
  missing outside the repo; boss_trigger loader, external
  relay-trigger dir absent from this VM), verified identical
  on the clean tree via git stash. One intermediate failure
  (dispatch README no-em-dash test) was caused by this
  run's own README wording and fixed in the same run
  before committing.

## NOT proven here

- A live wd hash written by a running watchdog (the tick
  reads snapshots, not the wd hash; no live Redis on this VM).
- A Pax sign-off message for FND-029 (none exists; the claim
  is shared code references, nothing more).
- Any behavior change: detectors, thresholds, and store
  writes are untouched; this run only documented and pinned
  shapes that were already in code.
