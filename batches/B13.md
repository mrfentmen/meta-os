## Port rules (binding — from the rust-port skill)

- **Port behavior, do not redesign.** The source is the specification: same inputs, outputs, edge cases, error shapes. If the original does something odd, port the oddity and note it.
- **Tests first** where tests exist; then the code. Parity is case-by-case, not 'similar coverage'.
- **Python/Node originals stay untouched** and remain the live fallback until this batch is PORTED.
- **Shared types live in the owning crate** — depend on them, never copy-paste types between crates.
- **Use the `rustdocs` MCP tools** for crate APIs instead of guessing them.
- Small commits, push often; read the live tip before every push; **never force-push**.

## Parity list

- No test files are assigned to this batch in the batch map. Parity = behavior-for-behavior match against the source files above, reviewed against the source's own callers and any tests named in Known traps.
- Exclusion-blocked cases (tests needing the excluded `relay_common`/viewer code) are listed by name in the completion report — marked, never dropped, never faked green.
