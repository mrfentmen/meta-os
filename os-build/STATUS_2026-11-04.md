## Five bugs found by looking at the screen tonight

1. **The dock grew a duplicate set.** `meta-desktop.sh` wrote launchers but
   never cleared them, so a second provision stacked a second copy: 34 items
   with imperium, trio, dashboard, board and calendar each in it twice. It now
   rewrites the set from scratch every run.
2. **Trio opened the right page unstyled.** The console links `../styles.css`,
   but it was installed at `/usr/share/metaos/imperium`, where that path falls
   off the end of the tree — so it drew as bare HTML with blue underlined
   links, the exact "it's a website" look the tile exists to kill. It is served
   from `/opt/face-site/imperium/` now, and provision installs the app so the
   image stops carrying an old copy.
3. **The image had no `sudo` at all.** `sudo: command not found` while `meta`
   sat in the sudo group, because the base build used `--no-install-recommends`
   on a package list without sudo. Added to the ISO list, and installed in this
   image with a live-style NOPASSWD drop-in.
4. **main's branding payload had regressed to an early draft** — a 34-line top
   bar pinned to the bottom edge with an "Applications" button, no grub theme,
   no splash frames, no icon theme. That is what put a stock-looking bar on the
   screen after syncing from `main`. Restored from the working checkout.
5. **The terminal was white in one place and dark in another.** The Meta
   terminal colours shipped as a comment in a doc; `xfce4-terminal`'s first
   window also starts a server that owns the settings for the rest, so a
   session with no user `terminalrc` kept the stock colours for good. The
   session now writes the user's `terminalrc` at login, before any terminal
   exists.

## Still open (do not claim these)

- **Clicking every tile with a real mouse in the guest** is not proven end to
  end. QEMU's `input-send-event` never reached the usb-tablet in this harness
  (no cursor, no clicks), so clicks were driven by `xdotool` inside the guest
  and the tiles were otherwise opened with `gtk-launch`. The plank item →
  `.desktop` → program chain is proven; the physical click path is not.
- `os-build/tools/dock_click_through.sh` does the click sweep but needs a
  harness whose pointer works; its first run picked plank's 10×10 helper window
  instead of the bar and reported 27 false NOTHINGs — fixed to pick the wide
  window, not re-run on a machine with a working pointer.
- Calamares is still untested. There is no install-to-disk proof.
- The ISO has not been rebuilt from this tree tonight; only the ext4 image was
  synced and booted. `merge-layers.sh` now includes `sudo` for that build.
- `dock_click_through.sh` and the captures in this commit are the only new
  tooling; nothing else was added.
