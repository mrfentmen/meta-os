# Services against the frozen ABI (BF4-07)

Generated by `os-build/layer1/gen_services.py` — do not edit by hand.
Regenerate after any change under `services/`, and the table follows.

**What this measures.** For each service, the `sys_*` externs reachable from its
sources through `import` (not the ones it merely mentions in a comment), and the
native run that drives it, if there is one. A service whose calls are all inside
the freeze is *runs on the proven ABI*. A service that reaches an extern outside
it is *needs a proposal* — the kernel cannot run it today, and no amount of green
native output changes that, because the host shim is substituting for a kernel.

## Class 3 — host-only forever

There is no service in this corpus whose *purpose* is host-only. The host-only
surface is the shim itself (`os-build/layer1/host/host_shim.c`), which refuses
five calls on purpose rather than faking them; that refusal is what makes the
native runs evidence. Nothing in `services/` is classified here, and this section
says so instead of listing a fake entry.

## What this table cannot tell you

- A green native run does not mean the service ran on the kernel ABI. It ran
  against `host_shim.c`, a linker-level substitute. The `sys_*` column is the
  part that transfers.
- `sys_ticks` is used by almost every waiting service and is **not** in F1. Until
  a proposal lands, "runs on the proven ABI" means "its calls are all in the
  freeze", not "the freeze is sufficient to boot it".
