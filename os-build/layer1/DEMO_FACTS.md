## Numbers this lane does not own

These are the numbers a services demo is most likely to be asked for, and none of
them is measurable from `services/`:

- **Boot time to the shell.** No boot log exists in this checkout. The kernel's
  milestone evidence lives in `os-build/SCOREBOARD.md`, which on this branch records
  no K1 boot log. Quote Milo's gate file, not this one.
- **Services started at boot.** `BOOT_PLAN.md` is a plan; `bootorder_check.py` proves
  the order is acyclic, not that a supervisor executed it. Nothing starts a service.
- **Memory used at runtime.** `size_audit.py` measures fixed storage declared in the
  source. Stack depth, struct padding, code size and `.rodata` are not in it.

## What a demo can say without overclaiming

Safe, because each sentence is a row above:

- "29 service programs build and run on this machine, 1097 checks passing."
- "17 services need no kernel call at all; 8 need a syscall the freeze does not have."
- "The corpus typechecks as 35 ok, 0 failed."

Not safe:

- "The OS runs these services." Nothing starts a service process; the runs are host
  processes against a substituted syscall surface.
- "The network stack works." The protocol pack talks to itself through an in-memory
  link; there is no NIC and no wire.
- "The filesystem persists." The backend is RAM, and the test proves a remount
  within one process, not a reboot.
