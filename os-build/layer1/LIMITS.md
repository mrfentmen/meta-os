# Limits, and the test that tries to break each one (BF4-17)

Generated by `os-build/layer1/gen_limits.py`. Every numeric limit-like constant in
`services/` is listed. **78 of 95 are exercised by a test**; 9 are not limits at all
(bit flags or dead declarations), and 8 are real limits no host driver can reach.
**0 remain UNPROVEN.**

Three outcomes are different claims, and the table keeps them apart:

- **Proven** — a test reaches the enforcing code with a value on the wrong side.
- **Not a limit** — a bit flag, or a constant nothing reads. No test could prove it,
  because there is no edge to cross.
- **Unreachable** — the code enforces it, but the host cannot produce the input. Each
  row names the structural bound so the claim can be checked.

Nothing is marked proven because it "looks covered".

## Why this document exists

A quota test is the only kind of test that fails in a way nobody notices: the
code works at every size below the limit, so ordinary use passes, and the
failure only appears on the day the data is big enough — which is the day it
matters. Enumerating the limits is the cheap half; the table above is the half
that says which ones are still guesses.
