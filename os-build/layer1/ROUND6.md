| Constant | Where | What that means |
|---|---|---|

| `CK_MAX_BLOCKS` (64) | `fs/fsck.goose:36` | fsck sizes from `MAX_DISK_BLOCKS`; this is a second copy nothing compares |

## 3. Two real bugs, found by driving the edges

Neither was reachable by any existing test, which is the point of the exercise.

### 3.1 `display.text_wrap` crashed on its first call

`LineList { spans: [] }` builds a **zero-length** array, then the fill loop writes
`spans[0]` → `index 0 out of bounds (length 0)` at `display/text.goose:62`. Nothing
in the corpus called `text_wrap`, so a module whose status line read RUNS had a
crash in its first loop. Fixed by constructing the array at full size
(`[Span { .. }; 16]`), and the same defect class was fixed earlier in the round in
`common/json/json.goose`, `common/table/table.goose` and `watchdog/metrics.goose`.

### 3.2 The escape parser corrupted its last parameter

`ESC_PARAMS_MAX` is 4. On a fifth `;` the parser kept `nparams` at 4 and then
**kept appending digits into slot 3**, so `ESC [ 1 ; 2 ; 3 ; 4 ; 5 ; 6 H` arrived as
row 1, column **456**. A hostile write could aim the cursor anywhere by appending
digits. Fixed with an explicit `drop` flag: parameters past the array are consumed
and discarded, and the first four stay the first four. `t80` asserts both
(`esc_param(p, 3) == 4`, `esc_param(p, 4) == -1`).
