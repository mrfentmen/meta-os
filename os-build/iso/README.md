# MetaOS 1.0 — boot + installer lane (Buffy)

Owner per `os-build/METAOS_1.0_12H_PLAN.md`: **Plymouth splash, Calamares
preseeded with Meta branding, install-path testing in VM.** Acceptance is
stated there: the ISO installs preseeded to a fresh disk and reboots into
the login screen; the proof is VM screendumps.

Base plan: Xubuntu core remastered with Cubic, x86_64, tested in UTM/VM.
The bare-metal Rust kernel is the 2.0 track and is not on this path.

## State, stated plainly

| artifact | state | evidence |
|---|---|---|
| Plymouth theme (`plymouth/metaos/`) | **WRITTEN, UNRUN** | structure lint + PNG checks; no plymouth binary on this Mac |
| Calamares config + preseed (`calamares/`) | **WRITTEN, UNRUN** | YAML parses, module refs complete, preseed assertions pass |

| VM proof harness | **PLUMBING PROVEN** | `--dry` captured a real QEMU framebuffer (see `proof/`) |
| ISO | **NOT BUILT** | needs a Linux host with root (Cubic chroot, or xorriso + squashfs-tools) |
| Install → login screendumps | **NOT RUN** | needs the ISO above; this is the acceptance artifact, not a claim |

Nothing in this lane has booted. Do not read "configs pass" as "installer
works"; the validator proves structure, not execution.

## What "preseeded" means here (read before promising a one-click install)

Calamares 3.x has **no unattended mode** and no config key for a plaintext
password. Everything except the password is pre-answered: locale, keyboard,
user name, disk layout (erase, GPT + EFI, ext4, no swap), reboot pre-checked,
no network package step. The operator still types the password on the user
page and clicks Install. That is why the acceptance proof is a screendumped
walkthrough, not a headless script — and why `vm_install_proof.sh --keys`
exists as a best-effort driver with `--vnc` for the typed field.

## Build

Two paths. Both provision the same payload; only the packaging differs.

### A. Cubic chroot (Hana's base lane owns the project)

```sh
sudo os-build/iso/build_iso.sh --root /path/to/cubic/custom-root
# then press Generate in Cubic; output name: metaos-1.0-amd64.iso
```

`provision.sh` installs the theme, Calamares config, autostart entry and the
in-target hook into the chroot, installs `calamares plymouth plymouth-themes`
if missing, and rebuilds the initramfs so the live boot shows the splash.

### B. Patch a base ISO (no Cubic, Linux + root)

```sh
sudo os-build/iso/build_iso.sh --iso ~/Downloads/xubuntu-24.04.3-desktop-amd64.iso \
     --out os-build/iso/metaos-1.0-amd64.iso
```

Extract → unsquash → provision → re-squash (matching the base compression) →
rebuild with `-boot_image any replay`, so the base ISO's El Torito and hybrid
MBR are reused instead of hand-written per release. Output sha256 is written
next to the ISO.

Base ISO is a parameter on purpose: the plan names Xubuntu+bCubic, and the
exact point release is Hana's call for the base lane. The patch path does not
depend on which flavour's installer ships on the base, because Calamares is
installed and launched from our own autostart entry.

## Prove it

```sh
# Everything that can be checked without root or Linux:
os-build/iso/tools/check_configs.py          # 36 assertions, exit 0 = structure only
os-build/iso/build_iso.sh --check            # same + tool readiness on this host

# Harness plumbing, no ISO needed:
os-build/iso/tools/vm_install_proof.sh --dry

# The acceptance run (Linux host, ISO present):
os-build/iso/tools/vm_install_proof.sh --iso metaos-1.0-amd64.iso \
     --keys ret,ret,ret,ret --reboot
```

Artifacts land in `proof/<utc-stamp>/`: `INDEX.md`, one PNG per stage
(`01-splash`, `02-live-desktop`, `03-installer-welcome`, `04-key-*`,
`05-installed-login`), `serial.log`, `qemu.pid`. Frames are QEMU's real
framebuffer via QMP `screendump` — not renders. `docs/theme-mock.png` is the
only mock in the tree and is labelled as such in its manifest entry.

Stage waits default to 25s / 150s / 75s because TCG is slow; override with
`WAIT_SPLASH`, `WAIT_DESKTOP`, `WAIT_INSTALLER`, `WAIT_LOGIN`.

## Original-asset rule

Every pixel is generated by `assets/make_assets.py`: a ring + dot mark and a
5×7 block wordmark drawn as rectangles, so no font file ships and no Apple
artwork, icon, font or pixel-layout is referenced. `dot.png` is copied from
OC1's `os-build/face/plymouth/metaos/ring-dot.png` so both spinners share one
dot; provenance is recorded in `assets/MANIFEST.json` and the validator
re-hashes it. `check_configs.py` fails the lane on any shipped `.ttf/.otf/
.icns` or any Apple-adjacent string outside a comment.

## Not this lane

- Greeter/lock-screen theme, dock, panel, GTK/Papirus recolour — OC1.
- Base package list, user accounts, first-boot — Hana.
- Agent layer preinstall/autostart — OC2.
- Kernel 2.0 pieces (framebuffer, demand paging, user loader) — Rowan.

The installer touches two of their surfaces by design: it enables
`lightdm.service` and writes `/etc/lightdm/lightdm.conf.d/90-metaos.conf`
with autologin **disabled** (login screen is the front door), and it leaves
`/usr/share/metaos/` as the landing zone for OC1's theme package.
