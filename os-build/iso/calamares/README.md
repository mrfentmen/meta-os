# MetaOS 1.0 — Calamares install configuration

OEM-style install of our single-squashfs image
(`casper/filesystem.squashfs`) to disk, from the live session.
Config only. Nothing here boots or emulates anything.

## Where these files go in the live rootfs

Installed by `os-build/iso/provision.sh` (the `calamares` section;
verified against provision.sh lines 65-86 on branch
`origin/opencode1/boot-installer`):

| repo path (this dir) | live rootfs path |
|---|---|
| `calamares/settings.conf` | `/etc/calamares/settings.conf` |
| `calamares/modules/*.conf` | `/etc/calamares/modules/` (whole dir, incl. `umount.conf`, `mount.conf`) |
| `calamares/branding/metaos/` (all of it: `branding.desc`, `stylesheet.qss`, `*.png`, `slideshow/`, `make_slides.py`) | `/etc/calamares/branding/metaos/` |
| `calamares/meta-branding.sh` | `/usr/local/lib/metaos/meta-branding.sh` (runs in the target chroot via the `meta-branding` shellprocess instance) |
| `calamares/branding/metaos/productIcon.png` (copy) | `/usr/share/metaos/installer.png` (the installer `.desktop` icon) |

Pre-existing `/etc/calamares/settings.conf` (if the base ever ships one)
is preserved as `settings.conf.base-flavour`, not overwritten blindly.

Note on `source id metaos-desktop`: that id lives in the ISO-level
`casper/install-sources.yaml` (written by `merge-layers.sh`) and tells the
live boot which squashfs layer set to use. It is NOT a Calamares
`unpackfs.conf` key — upstream `unpackfs.conf` accepts only
`source`/`sourcefs`/`destination` plus optional
`exclude`/`excludeFile`/`weight`/`condition`/`optional`. Do not add an
`id:` key there; it would be silently ignored. `unpackfs.conf` here
points at the live path `/cdrom/casper/filesystem.squashfs`.

## Module sequence (settings.conf)

show: `welcome locale keyboard partition users summary` — then exec:
`partition mount unpackfs machineid fstab locale keyboard localecfg
users displaymanager networkcfg hwclock bootloader packages
meta-branding umount` — then show: `finished`.

- No network-dependent step in the critical path: `packages.conf` sets
  `update: false`, `upgrade: false` and only *removes* live-session
  packages (`calamares`, `ubiquity`) from the target; `networkcfg`
  copies the live session's existing network config to the target and
  performs no downloads.
- `umount` (`emergency: true`, upstream-verified content) is the last
  exec job; `finished` is a trailing show page (upstream canonical
  form), with reboot pre-checked.
- `users.conf` preseeds name/login but Calamares 3.x cannot preseed a
  password: the operator types it on the user page. There is no
  unattended/headless install; the acceptance proof is a screendumped
  walkthrough.
- Style keys in `branding.desc` are the Capitalized upstream enum names
  (`SidebarBackground`, `SidebarText`, `SidebarTextCurrent`,
  `SidebarBackgroundCurrent`): that is exactly what
  `Branding::styleString` looks up and what the C++ widget sidebar
  (`ProgressTreeDelegate`) consumes. The lowercase form most distros
  ship does not match those lookups. Palette is the installer spec:
  blue `#1877F2`, white `#EDF5FF`, black `#070B16`.
- `slideshow:` (image list, paths relative to the branding dir) is
  REQUIRED: upstream `Branding` bails (exit 1) when the key is absent.
  Slides are generated by `branding/metaos/make_slides.py` (800x450
  PNGs, ring + block-glyph wordmark, no fonts, no artwork).
- Visible strings say MetaOS 1.0 only. Remaining upstream-vendor words
  (`Xubuntu`/`Ubuntu`/`ubiquity`) appear solely in config comments and
  the machine-readable `ID_LIKE=ubuntu` os-release field (kept for
  apt/tooling compat), never on a user-visible surface.

Upstream references checked (2026-11-03, `calamares/calamares` branch
`calamares`): `settings.conf`, `src/modules/unpackfs/unpackfs.conf`,
`src/modules/umount/umount.conf`, `src/branding/default/branding.desc`,

precedents (KaOS capitalized style keys; winesapOS `slideshow: []`).

## Live-install test — OUT OF SCOPE for this lane

No VM/QEMU boots were run here (config only, per fence). Before this
installs a real disk, someone with the boot harness must prove:

1. Calamares starts from the live session with this branding (no FATAL
   on `slideshow:`/`style`, no `Unknown branding *style* entry`
   warnings — those warnings would mean the provisioned Calamares
   predates the Capitalized-key behavior).
2. `unpackfs` finds `/cdrom/casper/filesystem.squashfs` on the merged
   ISO and the full exec sequence completes offline (no network in the
   proof VM).
3. The installed system boots to the LightDM login (no autologin),
   shows the Meta splash, hostname `metaos`, and never autostarts the
   installer.
4. The `finished` page reboot button works (`systemctl -i reboot`).
5. Slides render sanely in the exec pane (800x450 scaling/cropping).
