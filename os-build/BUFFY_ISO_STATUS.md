## RK-007 — the image exists, the boot does not

The kernel ELF builds (4.8 MB, `bootloader_api` 0.11.17), the host-side
builder compiles, and it produces a real BIOS disk image:

```
rustup component add llvm-tools-preview --toolchain nightly
cargo +nightly build
./target/debug/rk007-builder ../../../kernel/target/x86_64-unknown-none/debug/metaos-kernel /tmp/metaos-rk007.img
# rk007-builder: image /tmp/metaos-rk007.img (6784000 bytes)
```

Two defects were found by running it instead of reading it:

1. `create_disk_image(path)` returns `()`, and the code called `.display()` on
   the result — the crate had never compiled.
2. `llvm-tools-preview` was missing, so the bootloader build script died with
   `failed to get llvm tools: NotFound` before the builder's code was reached.

Both fixed on `bond/rk007`. The image is a build artifact and is not committed.

To finish, run on the 32GB MacBook — `iso/tools/boot_kit.sh --build` does all
four steps, and `boot_log_verdict.py` turns the serial log into PASS/FAIL rows:

```sh
iso/tools/boot_kit.sh --check
iso/tools/boot_kit.sh --build --out /tmp
qemu-system-x86_64 -drive format=raw,file=/tmp/metaos.img -serial file:/tmp/boot.txt -nographic -no-reboot -m 512M
python3 iso/tools/boot_log_verdict.py /tmp/boot.txt
```

## What runs, and what it says

```
iso/tools/verify_lane.sh
  == syntax            12 scripts and modules, all parse
  == static checker 115 passed, 0 failed, 0 skipped
  == tests             6 files, all PASS
  LANE GREEN
```

The checker is file-level and says so: it parses every YAML/INI/JSON/XML file,
checks that every image and launcher the configs name exists, that every
`Exec` resolves to a package or a shipped binary, that the dock is exactly the
frozen five, and that each generator's committed output is byte-identical to
what it would write now. It does not prove a single thing about a running
system.

## The fifth app, and the first-login fix

`agent-status` was the one frozen ID with nothing behind it. It now ships
(`meta-agent-status`, reads the registry, heartbeat, job queue and three
ledgers; writes nothing) and the checker walks the frozen table so a missing
launcher fails the gate by name.

`apply.sh` used to write dock items into `/home/meta`. Calamares creates the
account after the install, with the name the user types, so that path would
never exist. Dock items now land in `/usr/share/metaos/dock`, and
`meta-first-login` copies them into the real `$HOME` once, setting the backdrop
on every property Xfce reports rather than only `monitor0`.
