# R13-052 — devices restart / state survival

Status: **GAP FILED — no process or state file**.

## Requested condition

Kill `services/devices` mid-work, restart it, and record exactly what state survived, what
was lost, and what it re-did. Proof requires before/after state hashes plus a restart log.

## Evidence

`services/devices/devices.goose:130-131` populates the table from `BootInfo` (`dev_add(DEV_SERIAL, ... boot.serial.port ...)`); the rest of the table is static memory. There is no save/load or state-file path.

## State ledger

| Question | Answer |
|---|---|
| Survived | Nothing. The table is rebuilt from BootInfo on the next initialisation. |
| Lost | Device state transitions (READY/FAULT/ABSENT), the hot-plug queue and its subscriber mask. |
| Re-did | A restarted process calls the table initialiser again and re-derives base devices from BootInfo; devices that faulted after boot read as healthy until they fault again. |

## Gap

No devices process, no state file and no kill harness. A restart hash would hash a table that cannot be reached across processes.

## Owner

devices persistence; B-L1-113.
