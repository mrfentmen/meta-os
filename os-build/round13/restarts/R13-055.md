# R13-055 — display restart / state survival

Status: **GAP FILED — in-memory consoles only**.

## Requested condition

Kill `services/display` mid-work, restart it, and record exactly what state survived, what
was lost, and what it re-did. Proof requires before/after state hashes plus a restart log.

## Evidence

`services/display/display.goose:69-72` resets `vcon_count`/`active`; each console's screen and history are static arrays (`history` as a byte ring). There is no save/load or state-file path.

## State ledger

| Question | Answer |
|---|---|
| Survived | Nothing. The console text, cursor and history are process memory. |
| Lost | All four virtual consoles: screen bytes, cursor positions, scroll history and the active index. |
| Re-did | A restarted process creates consoles from scratch; the boot log’s earlier paint is gone, so the first paint starts at the kernel cursor. |

## Gap

No display process and no state file. A restart hash would require a persistence layer the service does not have.

## Owner

display persistence; K2 console contract.
