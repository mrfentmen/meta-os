# R13-033 — dhcp under input past the size cap

Status: **GAP FILED — no maximum cap**.

## Requested condition

The task asks for a failure-path test of `services/dhcp` under “input past the size cap”, with the
recorded behaviour (refusal, error envelope, or crash) and a test exit code.

## Evidence

`nl -ba services/dhcp/dhcp.goose | sed -n '202,273p'`: `dhcp_parse` rejects `pkt.len < 240` (line 208) and option lengths past the packet (line 237), but never rejects a packet larger than a maximum. Builders use `u8[..576]`; the parser accepts any slice length.

## Observed behaviour

A 4,000-byte buffer is parsed in full; options after the DHCP payload are skipped as unknown. There is no `E_NOROOM`/`E_INVAL` for oversize input, so the requested refusal does not exist.

## Gap

Add an explicit maximum at the parser boundary (or document the absence) and pin it with a test. The builder cap alone is not a parser guarantee.

## Owner

dhcp parser; `tests/t114_dhcp_r11`.
