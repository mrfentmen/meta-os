# R13-037 — echo under disk full on write

Status: **GAP FILED — no disk write**.

## Requested condition

The task asks for a failure-path test of `services/echo` under “disk full on write”, with the
recorded behaviour (refusal, error envelope, or crash) and a test exit code.

## Evidence

`services/echo/echo.goose:8-22` is the whole program. It writes only `write_stdout("> ")`, `write_stdout("echo: ")`, the line and a newline. `grep -nEi 'disk|fs_|storage|file|write|full'` matches those stdout calls only.

## Observed behaviour

There is no file, block or storage write. A full disk cannot be observed; a full stdout/serial sink could fail, but the program ignores `write_stdout`'s return and has no error path.

## Gap

Disk-full is inapplicable. The real gap is that stdout write failures are unobserved; the program is entry-only and untested.

## Owner

echo program; dev-carrier stdout contract.
