# R13-049 — settings under timeout below the work size

Status: **GAP FILED — no timeout**.

## Requested condition

The task asks for a failure-path test of `services/settings` under “timeout below the work size”, with the
recorded behaviour (refusal, error envelope, or crash) and a test exit code.

## Evidence

`grep -nEi 'timeout|work|budget|deadline|ms' services/settings/*.goose` returns no matches. `st_put_int`/`st_import` validate type, range and printable bytes; there is no timer or work estimate.

## Observed behaviour

The settings store is synchronous and has no timeout. There is no work-size calculation to compare against a deadline, so the requested condition cannot be constructed.

## Gap

Timeout policy is absent from the unit. A caller-level timeout test would not exercise settings logic.

## Owner

settings API; caller timeout contract.
