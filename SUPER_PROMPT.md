# SUPER PROMPT — Meta OS Rust rebuild, deep task queue

This is the deep task queue under `TASKS.md`. **TASKS.md still governs WHO**: its
§ Buffy and § OpenCode sections own the blocks below, and its claim rules apply
(crew: bus line in room 1; fleet: branch `batch/B##` pushed before coding —
first claim wins). This file is the WHAT at task granularity: 259 file-level
tasks decomposed from `BATCHES.md`'s 591-file inventory. Every inventory file
is named in exactly one task; data/docs/asset files appear only in verify-carried
or embed tasks, never as ports.

How to work this queue:

- Claim a task by its id before starting: `TAKE T###` where your section's claim
  rule requires it (bus line for crew, your batch branch for the fleet). One task,
  one owner. If a task id is taken, take the next one.
- Work tasks in id order within your block unless a task's own text names a
  dependency (harness before cases in B31; tests before the code they pin where
  a batch lists both).
- The Python/Node source is the spec: port behavior, never redesign. Frozen
  contracts (job kind/id, result key/body, `/api/assess` v2 shape, queue lease
  semantics, the $75 Spark guardrail) are byte-for-byte — see
  `docs/RUST_REBUILD_PLAN.md` and `batches/B##.md` for the spec behind any task.
- Every task ends with the state it leaves behind: **UNCOMPILED** (written, not
  yet gate-1 compiled), a gate state, **PORTED**, or **CARRIED** — never ambiguous.
  Nothing counts as compiled from the Pax sandbox; gate 1 is Milo's VM (or the
  local Mac in the fleet topology), gate 2 is the boss's Mac.
- Python/Node originals stay untouched — they are the live fallback until a
  batch is PORTED. Tests needing the excluded `relay_common`/viewer code are
  recorded **exclusion-blocked** — never dropped, never faked green.
- Stall rule: three compile rounds on the same error class = park the task,
  write the blocker into the batch spec, move to the next task.

## State legend & reporting

- **DRAFT** — claimed, work in progress, uncompiled.
- **UNCOMPILED** — written and pushed, not yet compiled at gate 1.
- **GATE1** — compiles + parity passes at gate 1.
- **GATE2** — compiles + parity passes at gate 2 (the boss's Mac). The final word.
- **PORTED** — both gates + parity passed; the Rust port is live for that piece.
- **PARKED** — stalled under the stall rule; blocker written in the batch spec.
- **CARRIED** — data/docs/assets: inventoried, verified byte-identical, left in place.

A finished task is reported as one line: `T### done — <state>` (for example
`T042 done — PORTED` or `T117 done — CARRIED`), posted where the work was
claimed: the crew bus (room 1) for crew work, the control window for the fleet.
